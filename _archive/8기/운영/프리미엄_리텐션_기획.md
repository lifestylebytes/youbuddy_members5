## 1. 진단 (7기 데이터 기준)

**재구매를 만든 건 "효과를 확인한 경험"이었다.**

- 주간테스트 3회 완주자 재구매율 **80%** vs 2회 이하 **0%** (n=44)
- 재구매 5명 중 프리미엄 3명. 프리미엄 인원 대비 재구매율이 베이직의 약 3배
- 8기 얼리버드 구매 목표에서 "루틴" 33% (7기 3%) → 사람들은 **끊기지 않게 해주는 시스템**에 돈을 낸다

**그런데 앱 안에서 프리미엄의 가치가 잘 안 보인다.**

- 프리미엄 핵심(미팅·PT·코칭)은 주 1회라 앱 사용 20일 중 16일은 베이직과 화면이 거의 같음
- 잠금 기능(약점 복습 등)은 베이직에게 토스트 한 줄로만 거절됨 → "없는 기능"처럼 느껴지고 욕망을 못 만듦
- 결론: **매일 보는 화면에서, 프리미엄만 되는 걸 "보이게" 하되 기분 나쁘지 않게** 만들어야 함

## 2. 원칙 3개

1. **가리지 말고 보여주고 잠근다.** 베이직에게 프리미엄 콘텐츠의 "입구"까지 보여준다 (유의어 한 줄 노출이 정확히 이 패턴, 깊이는 잠금)
2. **모든 프리미엄 순간에 👑 라벨.** 프리미엄 멤버에겐 "내가 이걸 누리고 있다"는 리마인드 = 리텐션, 베이직에겐 다음 단계 = 업셀
3. **조르지 않는다.** 잠금 카드에 가격·구매 버튼 금지. "8기 프리미엄에서 열려요" 한 줄까지만 (판매는 개인톡)

## 4. 녹음 인증 2단계 시스템 (구현 완료 · 8th 로컬)

> 문제: 앱 인증만 하고 녹음(입으로 말하기)을 건너뛰는 멤버가 많음. 말하기가 코어인데 측정이 안 됐음.

**규칙**
- 앱 인증만 = **연한 하늘색** 칸 (녹음 대기)
- 카톡방에 녹음까지 올림 = **새파란색** 칸 · **이것만 완전한 인증**
- 체크 담당: **이지흔** (스태프 권한이면 누구나 가능, 운영자도 가능)

**스태프 워크플로 (구현됨)**
1. 홈 보드 위 **🎙 녹음 체크 모드** 버튼 (스태프/운영자에게만 보임)
2. 켜면 인증된 칸에 점선 테두리 → **칸을 탭하면 새파랑 토글** (재탭 = 해제)
3. 저장은 자동 (0.4초 디바운스, 토스트로 확인). 멤버 화면에는 다음 동기화 때 반영
4. 셀 툴팁에 "🎙 녹음까지 완료 / 녹음 대기" 표시, 보드 상단에 색 범례 상시 노출

**저장 구조 (SQL 변경 없음)**
- 고스트 멤버키 `__recording_checks__` 의 app_state 에 `{ checks: { "d16": { "김민영": true } } }`
- 기존 `get/upsert_member_app_state` RPC 재사용. 디렉토리에 없는 키라 보드·통계에 안 잡힘

**가이드 투어 정리 (구현됨)**: "녹음 제출"(11)과 "단톡 인증"(12)이 서로 다른 인증처럼 읽히던 것 → 한 스텝으로 통합. "앱 인증 → 녹음 제출 버튼 → 카톡방 업로드 → 새파란 칸" 단일 흐름 + 색 규칙 설명 포함.

**✅ 점수 정책 확정 (2026-08-04, 버디): C안 + 이중 사다리**

수료 기준은 낮추지 않는다. 녹음은 그 위의 상위 목표.

| 등급 | 기준 | 보상 |
|---|---|---|
| 🎓 수료 | 앱 인증 **18일+** (기존 그대로) | 단어집 PDF + 완주 배지 |
| 🔵 풀보이스 완주 | 새파랑(녹음 체크) **18일+** | 수료식 호명 + 특별 보상 (내용 추후 확정) |

- 중간 배지(15일) 없음. "진짜 목표는 새파랑 18일" 메시지를 명확하게
- 완주 판정은 서버 그대로(마이그레이션 불필요), 풀보이스는 recording_checks 로 클라이언트 집계
- 스태프 체크는 소급 수정 가능하므로 체크 지연이 배지 판정에 영향 없음
- 온보딩·투어 문구에 반영할 것: "수료는 18일 인증, 그중 녹음까지 18일이면 풀보이스 완주"
